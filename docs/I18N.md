# 介面字串與英文介面規範

v1.3.0 起 App 有「跟隨系統／中文（繁體）／English」三種介面語言。做法是**原文寫繁體中文、翻譯檔放英文**：
各介面檔照這份規範把使用者看得到的字串包進翻譯函式，英文翻譯最後統一由 I2 補進 `i18n/yt_dl_en.ts`。

> 這份規範在 PySide6 6.12 上實測過：`pyside6-lupdate` 抽得到 Python 檔裡的 `self.tr`、`QCoreApplication.translate`、
> `QT_TRANSLATE_NOOP` 和短名稱 `_tr`，`%n` 單複數也能用（`tests/test_i18n.py` 有完整流程的測試）。

## 1. 快速對照

| 情況 | 寫法 |
|---|---|
| QObject／QWidget 的方法裡 | `self.tr("開始下載")` |
| 不在 Qt 物件裡（模組函式、`staticmethod`、一般類別） | `QCoreApplication.translate("native_tray", "結束")`，或短名稱 `_tr("native_tray", "結束")` |
| 有變數 | `self.tr("找不到「{name}」").format(name=title)` |
| 有數量（**不要用 `self.tr`**，見 2.4） | `_tr("DownloadPage", "已選 %n 部影片", None, count)` |
| 同一個中文在不同地方意思不同 | 第二個參數寫說明：`self.tr("清除", "清除已完成的工作")` |
| 模組層級的常數（import 時就建立） | `QT_TRANSLATE_NOOP("native_queue", "排隊中")`，用的時候再 `QCoreApplication.translate("native_queue", value)` |
| 引擎回傳的錯誤、處理階段 | **不翻譯**，直接顯示（引擎已依語言回傳） |
| 使用說明的網址 | `i18n.guide_url("err-private")` |

## 2. 規則

### 2.1 原文寫繁體中文

- 翻譯函式裡的原文一律寫繁體中文（就是中文介面看到的字）。現有字串不必先改寫成英文，包上翻譯函式就好。
- 用一般使用者看得懂的說法，不出現 yt-dlp 術語或命令列參數。
- 各工作包**不用寫英文翻譯，也不要改 `i18n/` 底下的檔案**；英文由 I2 統一補。

### 2.2 只用這幾種翻譯函式

`pyside6-lupdate` 是照「函式名稱」找字串的，**自己包一層函式（例如 `def t(s): return self.tr(s)`）會抽不到**。只能用：

1. **`self.tr("…")`**：在 QObject／QWidget 子類別的方法裡。context 是**寫這行程式的類別名稱**（子類別繼承下來也沿用父類別的翻譯，實測過；但有 `%n` 的字串例外，見 2.4）。
2. **`QCoreApplication.translate("<context>", "…")`**：其他地方。context 規則：
   - 在類別裡（例如 `staticmethod`、`classmethod`、非 QObject 的類別）用**類別名稱**，和 `self.tr` 同一組。
   - 模組層級的函式用**模組檔名**（不含 `.py`），例如 `"native_tray"`、`"url_handoff"`。
3. **短名稱 `_tr`**：嫌 `QCoreApplication.translate` 太長，可以在模組開頭寫

   ```python
   from PySide6.QtCore import QCoreApplication

   _tr = QCoreApplication.translate  # 名稱固定是 _tr，tools/i18n_update.py 只認得這個
   ```

   然後 `_tr("native_tray", "結束")`。**一定要是「指定」不是自己寫函式**，名稱也一定要是 `_tr`（工具用 `-tr-function-alias translate+=_tr` 登記）。
4. **`QT_TRANSLATE_NOOP("<context>", "…")`**（從 `PySide6.QtCore` import）：只標記、不翻譯，給 import 時就建立的常數用，見 2.6。

字串要直接寫在呼叫裡（字面字串）。下面這些都抽不到：

```python
self.tr(label)                 # ✗ 變數
self.tr("開始" + "下載")        # ✗ 運算出來的字串
self.tr(f"已完成 {n} 部")       # ✗ f-string
```

### 2.3 不用 f-string；變數用 `{name}` 佔位

翻譯完再 `.format()`。佔位名稱要有意義，翻譯的人才知道是什麼：

```python
# ✗ 錯：f-string 在翻譯前就把變數填進去，翻譯檔裡找不到這句
QLabel(self.tr(f"找不到「{title}」"))

# ✓ 對
QLabel(self.tr("找不到「{title}」").format(title=title))
```

- 字面的大括號要寫兩個：`"{{ }}"`。
- 不要用 `%s`、`%1`（`%n` 例外，見下一節）。

### 2.4 數量用 `%n`

```python
# 參數：context、原文、說明（沒有就給 None）、數量
QCoreApplication.translate("DownloadPage", "已選 %n 部影片", None, count)
_tr("native_queue", "%n 個工作失敗", None, failed)
```

- **有 `%n` 的字串不要用 `self.tr`**，一律用 `QCoreApplication.translate`／`_tr` 並寫明類別名稱（在類別裡）或模組名稱。
  原因：PySide6 6.12 的 `self.tr("…%n…", "", n)` 在**子類別**物件上不會沿用父類別的翻譯，英文介面會顯示中文（實測；
  沒有 `%n` 的 `self.tr` 沒這個問題）。
- Qt 會把 `%n` 換成數字，英文翻譯可以分單數（`%n video`）和複數（`%n videos`）。
- 同一句有數量又有其他變數：`_tr("PlaylistDialog", "「{name}」還有 %n 部", None, n).format(name=name)`。
- 不要自己寫 `if n == 1` 判斷單複數，也不要把數字用 `{count}` 塞進去（英文就沒辦法分單複數）。

### 2.5 不把句子拆成好幾段拼接；預留英文寬度

英文語序和中文不同，一句話要是**一個完整的翻譯字串**：

```python
# ✗ 錯：英文沒辦法調整語序
msg = self.tr("已下載") + " " + str(n) + " " + self.tr("部影片到") + folder

# ✓ 對
msg = _tr("QueuePage", "已下載 %n 部影片到 {folder}", None, n).format(folder=folder)
```

- HTML 或連結也整句包進去：`self.tr('看<a href="{url}">使用說明</a>').format(url=i18n.guide_url())`。
- 英文通常比中文長約 1.5 倍（「解析」→ Analyze）。按鈕、選單、標籤**不要用 `setFixedWidth`／`setFixedSize` 寫死寬度**，用 layout 自動決定；真的要限制就用 `setMinimumWidth`，或留 1.5 倍空間。
- 長說明文字要 `setWordWrap(True)`。

### 2.6 import 時就建立的字串

模組層級的 dict、list、class 屬性在 `import` 時就算好了，那時翻譯還沒裝上，會一直是中文。改成先用 `QT_TRANSLATE_NOOP` 標記，**顯示的時候**再翻譯：

```python
from PySide6.QtCore import QCoreApplication, QT_TRANSLATE_NOOP

STATUS_TEXT = {
    "queued": QT_TRANSLATE_NOOP("native_queue", "排隊中"),
    "paused": QT_TRANSLATE_NOOP("native_queue", "已暫停"),
}

def status_label(status: str) -> str:
    return QCoreApplication.translate("native_queue", STATUS_TEXT[status])
```

`QT_TRANSLATE_NOOP` 和之後的 `translate` 要用**同一個 context**。

### 2.7 引擎的文字不在 App 端翻譯

引擎（`server.py`）回傳的錯誤訊息、處理階段（例如「排隊中」「合併影音軌」）由 `engine_messages.py` 依請求的
`Accept-Language` 回傳中文或英文。App 端直接顯示 `error`、`stage` 欄位，**不要再包翻譯函式**，也不要比對中文內容判斷狀態，
要判斷請用 `error_code`、`stage_code`。App 送請求時的標頭值用 `i18n.accept_language()`（`"zh-TW"` 或 `"en"`）。

### 2.8 不翻譯的東西

- 檔名、路徑、網址、影片標題、格式代碼（`mp4`、`1080p`）、品牌名稱（YouTube、FFmpeg）。
- 只寫進 log、不給使用者看的訊息。
- 測試裡比對文字：測試在中文介面下跑（沒有 install 英文翻譯），照原文比對即可。

## 3. 語言設定與 `i18n` 模組

`i18n.py` 提供（介面約定見 ROADMAP 第 5.5 節）：

| 函式 | 說明 |
|---|---|
| `i18n.install(app)` | 在 `QApplication` 建立之後、建立任何視窗之前呼叫。安裝 `i18n/yt_dl_<lang>.qm` 和 Qt 內建的 `qtbase_<lang>.qm`（標準按鈕、對話框）。回傳套用的語言 |
| `i18n.current_language()` | 目前介面語言：`"zh_TW"` 或 `"en"` |
| `i18n.get_setting()` | 使用者設定：`"system"`、`"zh_TW"` 或 `"en"` |
| `i18n.set_language(setting)` | 儲存設定（`QSettings("YTDownloader", "NativeApp")` 的 `ui/language`）。**重新啟動 App 才生效** |
| `i18n.guide_url(anchor="")` | 依語言回傳 `USER_GUIDE.md` 或 `USER_GUIDE.en.md` 在 GitHub 上的網址，可加錨點 |
| `i18n.accept_language()` | 給引擎 API 的 `Accept-Language` 值 |

- 「跟隨系統」看系統的介面語言清單，第一個認得的勝出：中文（不分繁簡）→ 中文（繁體），英文 → English，都不是 → English。
- 打包版（PyInstaller）從 `sys._MEIPASS/i18n/` 找 App 翻譯檔，從 `PySide6/translations` 找 Qt 翻譯檔；找不到就維持原文，不會出錯。
  `build_app.py` 要把 `i18n/*.qm` 打包到 `i18n/`，Qt 檔案過濾要保留 `qtbase_en.qm`、`qtbase_zh_TW.qm`（F 工作包）。

## 4. 翻譯檔與工具

```
i18n/yt_dl_en.ts   # 翻譯原始檔（XML，I2 用 Qt Linguist 或文字編輯器補英文）
i18n/yt_dl_en.qm   # 編譯後的翻譯檔（App 載入這個；也 commit，打包不用另外編譯）
```

```bash
python tools/i18n_update.py                 # 抽字串 + 編譯
python tools/i18n_update.py --no-release    # 只抽字串
python tools/i18n_update.py --release-only  # 只編譯
```

- 抽字串的範圍：專案根目錄所有 `.py`，排除 `server.py`、`engine_messages.py`、`build_app.py`、`ytdlp_update.py`。新增介面檔不用改工具。
- 抽字串會保留已有的翻譯、移除已經不存在的字串。原文改了一個字，舊翻譯會被標成「未完成」，要重新確認。
- 改了 `.ts` 一定要重新編譯 `.qm` 再 commit；`tests/test_i18n.py` 會檢查 `.qm` 是不是由目前的 `.ts` 編出來的。
- 實際試英文介面：`i18n.set_language("en")` 後重開 App，或在 App 的設定頁切換（C2）。

## 5. 範例：一個完整的介面類別

```python
from PySide6.QtCore import QCoreApplication, QT_TRANSLATE_NOOP
from PySide6.QtWidgets import QLabel, QPushButton, QVBoxLayout, QWidget

import i18n

_tr = QCoreApplication.translate

KIND_TEXT = {
    "video": QT_TRANSLATE_NOOP("DemoPanel", "影片"),
    "audio": QT_TRANSLATE_NOOP("DemoPanel", "音訊"),
}


class DemoPanel(QWidget):
    def __init__(self, title: str, count: int, kind: str):
        super().__init__()
        layout = QVBoxLayout(self)
        layout.addWidget(QLabel(_tr("DemoPanel", "「{title}」共有 %n 部", None, count).format(title=title)))
        layout.addWidget(QLabel(_tr("DemoPanel", KIND_TEXT[kind])))
        help_link = QLabel(self.tr('遇到問題？看<a href="{url}">常見問題</a>').format(url=i18n.guide_url("faq")))
        help_link.setOpenExternalLinks(True)
        layout.addWidget(help_link)
        layout.addWidget(QPushButton(self.tr("開始下載")))  # 不寫死寬度

    @staticmethod
    def empty_text() -> str:
        return QCoreApplication.translate("DemoPanel", "清單是空的")  # staticmethod 沒有 self，用類別名稱
```

App 啟動時：

```python
app = QApplication(sys.argv)
i18n.install(app)  # 在建立任何視窗之前
window = MainWindow()
```

## 6. 交給 I2 與審查時的檢查清單

- [ ] 使用者看得到的中文字串都包了翻譯函式（`self.tr`／`QCoreApplication.translate`／`_tr`／`QT_TRANSLATE_NOOP`）。
- [ ] 沒有 f-string、字串相加、自己包的翻譯函式。
- [ ] 數量用 `%n`（用 `QCoreApplication.translate`／`_tr`，不用 `self.tr`），變數用 `{name}` + `.format()`。
- [ ] 沒有寫死按鈕、標籤寬度。
- [ ] 引擎回傳的文字沒有再翻譯；判斷狀態用代碼不用中文。
- [ ] 沒有改 `i18n/` 底下的檔案（I2 除外）。
- [ ] 改了中文版 `USER_GUIDE.md` 的 FAQ，同一個 PR 也要改 `USER_GUIDE.en.md`，錨點（`err-…`）兩邊要相同。
